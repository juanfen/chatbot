# Go 开发风格与编码规范

## 1. 命名

- 包名全小写短词，避免下划线与驼峰。
- 导出标识符使用大驼峰，非导出标识符使用小驼峰。
- 接口命名以能力为中心（如 `UserRepository`、`TokenProvider`），避免 `IUserService` 风格。
- 常量采用语义化命名，分组常量使用 `const (...)`。

## 2. 注释

- 导出类型、导出函数、导出方法必须写 GoDoc 注释，首词以标识符名开头。
- 复杂业务逻辑和关键分支写简洁注释，禁止“翻译代码式”注释。
- TODO 必须带负责人或上下文，避免长期悬挂。

## 3. 格式

- 统一使用 `gofmt`（或 `goimports`）格式化，禁止手工对齐风格分歧。
- 单函数保持可读，过长时拆分私有函数。
- 错误处理采用“就近返回”，减少深层嵌套。

## 4. 分层与依赖

- Handler 依赖 Service，Service 依赖 Repository，禁止反向依赖。
- Controller/Handler 不直接操作数据库。
- DTO 与 Model 分离，避免接口层结构泄漏数据库细节。

## 5. 错误与日志

- 严禁忽略错误返回（除明确可忽略且有注释说明场景）。
- 业务错误使用可判定类型（如 `AppError`），统一映射到响应码。
- 日志使用结构化 logger（推荐 `zap` 或 `logrus`），禁止 `fmt.Println` 打业务日志。
- 记录错误时附带上下文字段（请求 ID、用户 ID、资源 ID）。

## 6. 安全

- 密码使用 BCrypt/Argon2 加盐哈希，禁止明文存储。
- JWT 白名单接口需显式维护，默认所有业务接口鉴权。
- 敏感配置不得提交仓库明文。

## 7. 配置

- 配置读取集中化管理（`internal/config`），禁止任意包直接读环境变量。
- 开发/生产配置分离，并支持最小化本地启动配置。
