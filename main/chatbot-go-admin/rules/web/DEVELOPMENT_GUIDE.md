# @web 开发规范（基于当前 SoybeanAdmin 2.1.0）

> 目的：让新增页面/组件/接口/状态管理都遵循当前仓库的实现方式，避免与现有约定（路由生成、请求封装、自动导入、样式体系、Pinia 模块边界等）产生冲突。

## 1. 技术栈与入口顺序

本项目基于：Vue 3 + Vite + TypeScript + Pinia + NaiveUI + UnoCSS，并使用 `@elegant-router` 做路由自动生成。

- 入口：`src/main.ts`
  - 初始化加载层/进度条/图标离线缓存/日期库
  - `setupStore(app)`：Pinia
  - `await setupRouter(app)`：Vue Router + guard
  - `setupI18n(app)`：vue-i18n
  - 挂载 `App.vue`

## 2. 代码风格（必须遵守）

### 2.1 TypeScript

- `tsconfig.json` 开启 `strict: true` 与 `strictNullChecks: true`
- 推荐：新增代码优先使用 `type`/`interface` 进行明确声明，避免 `any`
- 约束：尽量不要绕过类型系统（例如强行 `as`），除非你能解释其正确性

### 2.2 Vue 单文件组件（.vue）

当前代码库的组件实现方式基本都是：

- `<script setup lang="ts">`
- 通过 `defineOptions({ name: '...' })` 显式声明组件名（示例：`src/components/common/lang-switch.vue`、`src/components/custom/svg-icon.vue`）
- Props 使用 `interface Props` + `withDefaults(defineProps<Props>(), ...)`
- Emits 使用类型化 `defineEmits<...>()`

同时，eslint 对模板组件名大小写有约束（`vue/component-name-in-template-casing`）：模板里使用 `PascalCase` 形式的组件名。

### 2.3 格式化与校验

建议本地开发时把下面流程串起来（与你的 pre-commit 一致）：

- `pnpm typecheck`：`vue-tsc --noEmit --skipLibCheck`
- `pnpm lint`：`oxlint --fix && eslint --fix .`
- `pnpm fmt`：`oxfmt`

仓库默认已在本地移除提交钩子（不再强制 `pre-commit`）。如需保持一致性，建议在提交前手动执行：

- `pnpm typecheck && pnpm lint && pnpm fmt`

## 3. 目录结构约束（按“当前约定”写）

### 3.1 src/ 关键模块

- `src/router/`
  - `src/router/index.ts`：创建 router、选择 history 模式、注册 guard
  - `src/router/guard/`
    - `route.ts`：鉴权/路由初始化/权限路由校验
    - `progress.ts`：NProgress
    - `title.ts`：基于 `to.meta` 设置 `document.title`
  - `src/router/routes/`：常量/静态路由拼接与 Elegant Router 转 Vue Router
  - `src/router/elegant/`
    - 主要由 Elegant Router 生成（`routes.ts`/`imports.ts` 带 “Generated by elegant-router” 注释）

- `src/store/`（Pinia 模块化）
  - `src/store/modules/auth/`：登录态、token、userInfo、重置逻辑
  - `src/store/modules/theme/`：主题/暗黑/水印等
  - `src/store/modules/route/`：常量路由/鉴权路由初始化、menus、breadcrumbs、cache 管理
  - `src/store/modules/tab/`：多标签页管理

- `src/hooks/`（composition 的封装）
  - `src/hooks/common/*`：通用工具（如 `router.ts`、`icon.ts`、`form.ts`）
  - `src/hooks/business/*`：业务封装（如 `auth.ts`、`captcha.ts`）

- `src/service/`
  - `src/service/request/*`：请求实例与统一错误/鉴权/刷新 token 处理
  - `src/service/api/*`：按域名组织的 API 函数（通过统一 request 实例）

- `src/components/`
  - `common/`：公共 UI 组件
  - `custom/`：自定义基础组件（例如 `SvgIcon`、按钮图标等）
  - `advanced/`：高级/组合类组件（例如表格相关配置组件）

### 3.2 views（页面）

- 页面文件位于 `src/views/**`
- 内置异常页在 `src/views/_builtin/*`
- 示例主页在 `src/views/home/index.vue`

页面新增建议用脚手架生成（见第 4.4 节），避免手动破坏路由生成规则。

## 4. 新增功能的落地规范

### 国际化（i18n）

凡面向用户的文案（路由标题、页面、表格列头、表单、按钮、校验与提示等），必须在 **`src/locales/langs/zh-cn.ts` 与 `src/locales/langs/en-us.ts` 同步**维护同一套键结构；代码中使用 `$t('...')` 等与本项目一致的写法，**禁止**在 `.vue`/业务 `.ts` 里硬编码中英文字符串作为 UI 文案。新增业务模块优先放在 `page.<模块名>` 等命名空间下，并保证类型与 `App.I18n.Schema` 一致。

### 4.1 新增 API 接口

新增接口必须遵循“只通过 request 实例发请求”的原则：

1. 在 `src/service/api/` 下按业务域新增文件（例如 `user.ts`、`project.ts`）
2. 在对应文件里写一个导出函数，使用 `request<你的返回类型>({ ... })`
3. `src/service/api/index.ts` 里导出你新增的 API（当前 `index.ts` 已聚合 `auth` 与 `route`）

统一请求封装在 `src/service/request/index.ts`，关键行为：

- 自动拼接 `Authorization`（从 `localStg` 的 token 读取）
- 使用后端 `VITE_SERVICE_SUCCESS_CODE` 判断成功（默认语义：`code` 等于该值）
- 后端失败时根据环境变量处理：
  - `VITE_SERVICE_LOGOUT_CODES`：直接登出并 resetStore
  - `VITE_SERVICE_MODAL_LOGOUT_CODES`：弹窗确认后登出
  - `VITE_SERVICE_EXPIRED_TOKEN_CODES`：刷新 token 后重试原请求
- 错误展示使用 `window.$message?.error`，并用 `errMsgStack` 去重

因此新增 API 不要自己做登录态处理/刷新重试/弹窗逻辑，保持与现有封装一致即可。

同时必须遵守统一 HTTP 协议约定（强制）：

- `rules/web/HTTP_CONTRACT.md`
- 后端对应：`rules/server/HTTP_CONTRACT.md`

### 4.2 新增 Pinia store

Pinia 模块只做一个职责域，复用已有模式：

- 使用 `defineStore(SetupStoreId.XXX, () => { ... })`
- 逻辑尽量保持“无副作用的纯函数 + 少量副作用（请求/事件监听）”
- 需要全局重置时：暴露 `resetStore()`，并在鉴权/注销流程里统一调用

参考：

- `src/store/modules/auth/index.ts`：`resetStore()` 会清 token、重置自身 store，并在必要时触发跳转
- `src/store/modules/route/index.ts`：负责常量路由/鉴权路由初始化、menus、cacheRoutes
- `src/store/modules/tab/index.ts`：负责 tab 增删与路由缓存重置

### 4.3 新增路由/菜单能力

本仓库主要依赖 Elegant Router 来生成 `src/router/elegant/routes.ts` 与 `src/router/elegant/imports.ts`。

强烈建议：

- 不要手动编辑带有 “Generated by elegant-router” 的文件
- 新增路由优先通过创建 `src/views/**` 下的页面文件来让生成逻辑生效
- 如确需手动补充：
  - `src/router/routes/index.ts` 支持 `customRoutes`（当前为 `[]`）
  - 但权限字段（`roles`）与路由 meta 的来源要和 RBAC 校验逻辑一致（见 `src/router/guard/route.ts` 和 `src/store/modules/route/shared.ts`）

鉴权流程核心在 `src/router/guard/route.ts`：

- `to.meta.constant === true`：表示不需要登录态的“常量路由”
- `to.meta.roles` 决定是否需要对应角色
- 登录态不在且需要登录：跳 `login`，携带 `redirect`
- 已登录但路由无权限：跳 `403`

### 4.4 新增页面（推荐使用脚手架）

路由脚手架命令：`pnpm gen-route`（package.json 中脚本名为 `gen-route`，底层是 `sa gen-route`）。

该脚手架的约束来自 `packages/scripts/src/commands/router.ts`：

- 路由名支持：字母/数字/`-`/`_`（不支持空格与其他字符）
- `routeName` 使用 `_` 分隔层级：
  - 一层：`demo-route`
  - 两层：`demo-route_child`
  - 多层：`demo-route_child_child`
- group 路由：前缀 `_ignore_`（生成器提示示例中说明）

生成出来的 Vue 模板默认放在 `src/views/**` 下，并创建 `index.vue`（或带 params 的 vue 文件）。

新增完成后，建议直接 `pnpm dev` 看路由生成与页面是否生效。

## 5. 样式与图标规范（UnoCSS / SCSS / SVG 图标）

### 5.1 UnoCSS

UnoCSS 配置在 `uno.config.ts`：

- preset：`presetWind3({ dark: 'class' })` + `presetSoybeanAdmin()`
- 指令转换：`transformerDirectives()`、`transformerVariantGroup()`
- 现有快捷样式：`card-wrapper` => `rd-8px shadow-sm`

因此：

- 需要快速复用样式：优先加到 `shortcuts`（现成示例是 `card-wrapper`）
- 模板里使用 UnoCSS class（而非写大量行内样式）

### 5.2 SCSS 规范

`vite.config.ts` 对 SCSS 做了全局注入：

- 任何 `.scss` 文件里都会自动 `@use "@/styles/scss/global.scss" as *;`

所以：

- 不要在每个 scss 文件里重复引入 `global.scss`
- 新增变量/函数统一维护在 `src/styles/scss/global.scss`（遵循它现有的命名方式）

### 5.3 图标（SvgIcon + Iconify / 本地 SVG）

图标渲染统一使用 `src/components/custom/svg-icon.vue`：

- 本地 SVG：`<SvgIcon localIcon="no-icon" />`（localIcon 优先渲染）
- Iconify 图标：`<SvgIcon icon="heroicons:language" />`

本地 SVG 资源目录：`src/assets/svg-icon/`

图标自动导入与本地 icon collection 配置在 `build/plugins/unplugin.ts` 与 `build/plugins/unocss.ts`：

- `unplugin-vue-components` 会自动注册 NaiveUI 与图标组件
- SVG icons 的 symbol 注入 id 与 prefix 由环境变量控制（`VITE_ICON_PREFIX` / `VITE_ICON_LOCAL_PREFIX`）

新增本地图标时：

1. 放入 `src/assets/svg-icon/*`
2. 使用 `<SvgIcon localIcon="你的文件名(不含扩展名)" />`

## 6. 运行与提交建议

- 开发时：保持 `pnpm dev` 与 `pnpm typecheck/lint/fmt` 的一致性
- 提交时：优先使用脚手架集成的 `pnpm commit`（项目 README 明确其符合 Conventional Commits）
- 避免手动修改“Generated”文件：例如 `src/router/elegant/routes.ts`、`src/router/elegant/imports.ts`（带生成注释）
